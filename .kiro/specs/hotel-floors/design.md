# Design Document: hotel-floors

- `shared/src/world/hotel.ts`: `Hotel` holds `Map<RoomId, WorldSim>`; `moveUser(userId, roomId)` leaves the old sim and joins the new one (returns `welcome` for the new room). `RoomId = "lobby" | "hr" | \`project:${string}\``.
- Rooms: `world-server/rooms/lobby.json`, `hr.json`, `project-template.json`; `roomForProject(project)` fills the template (sign text through `sanitize`, max 32 chars).
- Furniture: `elevator` (interaction `elevator`), `directory_board` (`directory`), `door` (interaction `door` with a `to` room), `reception_desk` moves to the lobby.
- Protocol: client `go_to { roomId }`; server `floors { floors: FloorStatus[] }` pushed on change; `welcome` gains `roomId`. Messages from the engine are routed by `taskId → projectId → room`.
- Engine: job queue with `maxConcurrentJobs` (config, default 2); one active job per project; agent ids `<projectId>:<role>` in events, mapped to the room's agents by the world-server.
- Client: `ui/elevator.ts` (floor panel), transition overlay (CSS doors + floor number, reduced-motion: instant), HUD floor label, terminal scope toggle.
- Replay: `RunExport` gains `roomId`; the replay builds a hotel with the lobby and the recorded floor.

## Decisions made while implementing (tasks 1-3)

- **Rooms.** `RoomDef` gains `kind` (`project`, `lobby`, `hr`; absent = the old single office with all four agents) and `PlacedFurni` gains `to` (target room of a `door`). `roomAgents(room)` says who lives where: project rooms have Architect, Developer and QA, the lobby has the Builder, the HR office has nobody. `checkRoom` asks for computer/mailbox/board only in offices and for `home_*`/`desk` anchors only for the agents of the room. `roomForProject(template, project)` takes the template as an argument (shared cannot read files) and validates the result. The sign text is the room name: `sanitize` with control characters removed, at most 32 characters, falling back to the project id.
- **Entry point.** The `door` anchor of every room is the tile in front of its elevator, so a user who joins or changes floor stands at the elevator. `Hotel.atElevator(userId)` checks that, and the gateway accepts `go_to` only then (a reload that remembers a floor sends `go_to` right after `welcome`, when the user is still there).
- **Doors.** Using a `door` makes the sim emit `open_panel { panel: "door", data: { to } }` after the walk. The gateway never forwards it: it moves the user to `to` (only if the room exists).
- **Room files.** `lobby.json`, `hr.json` and `project-template.json` are new. `office.json` stays for now because the demo replay and the older shared/client tests still use it; it goes in task 5 when the replay builds its hotel.
- **Agent ids.** Events carry `ScopedAgentId` (`AgentId` or `<projectId>:<role>`, `ScopedAgentIdSchema` in `room.ts`). The runner and the steps keep emitting plain roles; `Store.appendEvent` rewrites a plain Architect/Developer/QA id to `<repoId>:<role>` using the repo of the job (known from `task.created`). Builder events and events of unknown jobs stay plain. `WorldSim.handleAgentEvent` and the gateway split the id, so rooms and clients only see roles. The activity throttle is per job and agent.
- **Queue.** `limits.json` has `maxConcurrentJobs` (optional in the schema, default 2). `JobRunner.start` throws `busy` when the project already has an unfinished job (also one that waits); otherwise the job is created and takes a slot or waits. A waiting job stays in `created`, and the engine emits `task.queued { position }` whenever its place changes (not for every job on every change). Cancelling a queued job ends it `cancelled` and frees its place. A slot is released when the job's loop ends, whatever the outcome.
- **Floor status.** There is no engine endpoint for it. The gateway keeps, per floor, the state of the current job and its queue place from the events, and `statusOfJobState` (shared) turns them into `idle | working(who) | waiting_approval | queued(position)`. `report_ready` and `failed` are set when a report arrives and stay until the user opens the mailbox on that floor (only the world-server knows what the user has read). A world-server that starts while a job runs does not know that job (the same limit as before).
- **Gateway.** `startGateway({ hotel, engine })` replaces `sim`. It keeps one `Floor` record per room (approvals, reports, activity, works, current job) and routes each engine event by `taskId -> room` (from `task.created`), then by the project in the agent id, then Builder -> lobby. It sends to the user only what belongs to the user's room, and drops sim output that is still queued when the user has left the room. The computer lists only the floor's project; `start_job`, `approve`, `job_details` and `deliver` for another floor are refused with `bad_message`; `register_project` and `remove_project` only work in the lobby. Floors are created and removed by `syncProjects` (at start, on every connection, after register/remove and when an event arrives for a room that does not exist); a failed `listProjects` keeps the floors as they are.
- **Client in between.** Until task 4 the client shows the lobby with placeholders: new draw recipes for elevator, directory board and door, and the elevator/directory panels show a note. It does not handle a second `welcome` yet.
- **Open for task 4.** The terminal's "All floors" option needs activity lines of other floors; today the gateway sends only the current floor's lines. Proposal: the client asks (`activity_scope`) and the lines get a `roomId`.

## Decisions made while implementing (tasks 4-5)

- **Terminal scope (resolves the open point of task 3).** Client message `activity_scope { scope }`; `ActivityLine` gains `roomId`, set by the gateway on every line. The scope lives on the connection and starts as `floor`. For `all` the gateway sends the other floors' buffered lines at once and their new lines later. The client sends it again after every `welcome`, because it reseeds the terminal with one floor. The terminal model puts late lines in time order and drops exact repeats.
- **Floor change in the client.** `PanelState` drops job, approvals, reports and repos on `welcome` (the new floor's pending approvals and job come right after). `floors` re-renders only the elevator and directory panels, so a computer form being typed is never redrawn. The team bar shows only the agents the welcome lists (Builder in the lobby, three roles on a project floor).
- **HUD.** Floor name in the top bar (hidden in compact layout) and an Elevator button. The button sends `use` on the room's elevator, so the avatar walks there and the panel opens on arrival (`go_to` is accepted only at the elevator). Its label counts the other floors that wait for the user.
- **Doors.** `ui/transition.ts`: `DoorSequence` (pure, injected timers, tested) with close 350 ms, hold 250 ms, open 400 ms, and a 4 s give-up. Started by choosing a floor; a welcome for another room plays it too (HR door, removed floor). Under reduced motion nothing shows. A `bad_message` error opens the doors again.
- **Remembered floor.** Live mode only (`agentlife-floor` in localStorage). After a (re)connection the client waits for the first `floors`, then sends `go_to` to the remembered floor if it exists; if it is not listed it waits 3 s before it forgets it. The demo always starts on the recorded floor.
- **Replay.** `ReplayTransport(exp, { lobby, hr, template })` builds a `Hotel` with the lobby, the HR office and the recorded floor, and the user starts on the recorded floor. It answers `go_to`, doors, `floors` and the elevator panel like the gateway; messages about the recorded job reach the user only on that floor, and coming back brings the pending approval and the job. `RunExport.roomId` is optional: an export without it (older recordings) gets `project:<repoId>`. The engine now writes it. `office.json` stays only for tests.
- **Playwright.** The config runs one worker (one user per world-server). The job-insight specs start on the haunted-todo floor and inject their messages after that floor's welcome.

## Decisions made while fixing the review (2026-11-12)

- **Project name in the scene (requirement 1.2).** `scene/door-signs.ts` draws the room name as text over the floor's elevator and its board; only `project:` rooms get signs (the lobby and the HR office have no project name). Names longer than 16 characters are cut with an ellipsis (`signLabel`); the server already sanitised the text. The signs live in the `objects` layer, so `clearScene` destroys them with the rest. The sign is not drawn on the door sprite itself, so it works with the existing furniture art.
- **Deferred messages when changing floors.** The review feared that messages deferred in a room the user left would arrive on return. `WorldSim.leave()` and `join()` already drop every deferred message of the user, and the gateway tick drains and discards the deferred queue of the rooms the user is not in. No code change was needed; `hotel.test.ts` now has a test that leaves and returns before and after the walk time.
- **Removed floor through the gateway.** `floors.test.ts` covers a user standing on a floor whose project disappeared: lobby `welcome` and a floor list without that floor.
- **New visits start in the lobby (2026-11-12, user feedback).** The remembered floor moved from localStorage to sessionStorage: a reload of the same tab still returns to the floor (requirement 2.2), but opening the hotel again starts at the entrance, which is where a hotel visit begins. The old localStorage key is removed on load.
